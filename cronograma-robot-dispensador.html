Recomendaciones del proyecto
⚠ Cuellos de botella críticos
Impresión 3D puede tardar 2–4 semanas extra → pedir piezas lo antes posible
Integración Arduino ↔ Raspberry Pi es el punto más difícil → investigar comunicación serial desde semana 1
API de IA tiene costo → tener alternativa gratuita (Gemini API) lista desde el inicio
Mecanismo dispensador: riesgo de atascos → diseñar con tolerancias generosas (+0.5mm)
"¿Cómo detecta al paciente?" → definir esto en diseño, no puede quedar sin resolver
✓ Orden recomendado de módulos
1° Dispensador (más mecánico, más tardado, todo depende de que funcione)
2° Base de datos y App (es el hub de toda la lógica del sistema)
3° Movilidad (puede ir en paralelo con el dispensador)
4° IA (integrar al final, cuando BD y app ya estén estables)
Regla: ningún módulo puede empezar integración sin pruebas individuales pasando
🔄 Si hay retrasos
Retraso en diseño → recortar investigación a 2 semanas en vez de 3
Retraso en movilidad → usar robot estático para la demo de agosto; agregar movilidad en Mejora Final
Retraso en IA → reemplazar temporalmente con botones en pantalla
Reasignar programadores a integración si desarrollo individual se estanca después de semana 13
No mover la fecha de FS5 (Meta Agosto): es el hito más importante del proyecto
📋 Claves para llegar a agosto
Feature freeze en semana 16: después de esa fecha, cero funciones nuevas
Cada módulo necesita 1 responsable de integración (sin vacíos de responsabilidad)
Documentar la API de cada módulo antes de la semana de integración
Las semanas 10–14 son críticas: no pueden tener retrasos acumulados
Cada jueves debe haber al menos 1 demo funcional, aunque sea pequeño
